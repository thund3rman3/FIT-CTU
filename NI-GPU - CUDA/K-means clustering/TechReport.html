K-Means Optimization with CUDA

Author: Josef Jech

This report focuses on comparison of the sequential and the parallelized CUDA implementations of the K-Means algorithm for clustering data into k clusters in an n-dimensional space. The numbers are stored in binary files and loaded into a vector (points) of 1D points, where the algorithm is the one who looks at the data like n-dimensional points. After that, the next vector (point_cluster_ids) is used to store the assigned cluster number for the point i.

1. Implementation of sequential k-means algorithm

First k points are selected as the initial cluster centroids. Then, the algorithm iteratively assigns each point to the nearest cluster. As the points have their clusters, new centroids are calculated. The process is repeated until convergence, which is determined by checking if any point's cluster assignment has changed in the current iteration. The time is measured using the std::chrono library.

2. CUDA Implementation and Performance

Implementation starts the same as the sequetial version, but it begins to differ with moving data to GPU data stuctures in the initialization phase. Points coordinates and initial centroids are copied to the GPU memory, and cluster ids are initialized like before. Newly old cetroids and new centroid sums are stored in GPU memory as well, and they are used to calculate new centroids in each iteration. Changed points and cluster counts are also arrays stored in GPU. In every iteration, three kernels are launched. The first one assigns clusters to points by calling function which calculates distance on GPU and uses atomicAdd to update number of changed points. And the second and the third one calculate new centroids by averaging the points in each cluster with help of atomicAdd. The time is measured using CUDA events. Number of blocks is always set to relative to the array used by the kernel (points or centroids) - (N + threadsPerBlock - 1) / threadsPerBlock.

How each parameter affected the final performance:

  • Dataset size (Points): The bigger the data, the better the speedup. Tests show that simply jumping from a 1-million to a 10-million point dataset multiplies the already massive speedup by an additional 1x to 2.3x.
  • Number of clusters (K): The more clusters you look for, the bigger the speedup. A higher number of target centroids fits better to the GPU, because its thousands of threads can calculate distances to multiple centroids in parallel.
  • Number of dimensions (N): Measurements show that the fewer dimensions there are, the higher the relative speedup multiplier gets. The biggest speedups actually happen in lower-dimensional spaces (like 1D or 2D).
  • Thread and Block configuration: For big datasets (like 10M points), the number of threads per block barely makes a difference. However, for smaller datasets (like 1M points), pushing the thread count to the extremes actually hurts performance (for example, run times worsened significantly when using 32 or 1024 threads). In tests, 256 threads per block did the best.
  • We see that the native data type (float) for GPU performs better than with (double), and that at least 2x.

3. Conclusion

Looking at the results, it's clear that using CUDA for the K-Means algorithm gives us a real performance boost (up to 900x in measured cases). The GPU really shines when the workload gets heavy what we see on measurements of millions of points. Measurements revealed that the most extreme relative speedups occur with a combination of a high number of target clusters (K) and lower dimensions . The GPU handles this setup well because its threads can calculate distances to many centroids in parallel, while going through the simpler math of low dimensions without hitting memory bandwidth bottlenecks. Additionally, the tests showed that pushing the thread count to the extremes is not always the best approach. Across the various test runs, using exactly 256 threads per block consistently emerged as the optimal setup to keep the GPU fully occupied.

Parallelizing K-Means with CUDA is pretty much mandatory if you want to work with massive, multi-dimensional datasets.
